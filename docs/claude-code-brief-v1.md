## Контекст

Мы строим AI-тьютора по математике для 5 класса (10–11 лет) для пилота в
Узбекистане. Модель работает не как свободный чат, а как ограниченный тьютор:
получает проверенную задачу, утверждённые подсказки и список типичных ошибок,
возвращает строго структурированное решение о том, как ответить ребёнку.

Твоя задача — **не построить тьютора**. Твоя задача — построить
**измерительный стенд**, который сравнивает несколько LLM на одинаковом наборе
педагогических ситуаций и говорит, какая из них ведёт себя корректно.

## Жёсткие ограничения

Нарушение любого из них делает весь эксперимент недействительным.

1. **Не изобретай математический контент.** Все задачи, канонические ответы,
   подсказки и типичные ошибки берутся ТОЛЬКО из `grade5_math_item_bank.md`.
   Не добавляй свои задачи, не «улучшай» формулировки, не исправляй математику.
   Если увидел ошибку в банке — запиши в `REVIEW_NEEDED.md`, не правь молча.

2. **Переводы на русский и узбекский — черновики, а не результат.** Ты можешь
   сгенерировать их, но каждый файл перевода обязан содержать
   `translation_status: draft_ai_generated` и предупреждение, что до проверки
   человеком результаты по этому языку невалидны. Никогда не помечай перевод
   как `reviewed`. Причина: если переводы делает ИИ, эксперимент измеряет
   качество твоих переводов, а не качество тестируемых моделей.

3. **Не трать деньги без спроса.** Бюджет — $25 предоплаченных кредитов
   OpenRouter на месяц. Перед КАЖДЫМ вызовом API оцени стоимость и покажи её.
   Полный прогон запускай только по явной команде пользователя. Сам — максимум
   smoke run (см. Фазу 4).

4. **Никаких данных детей.** Все ученики в тестах вымышленные. Ни имён, ни школ,
   ни возрастов сверх «Grade 5».

## Фаза 1 — Структура и схема

**Отобранные для первого прогона 5 задач** (выбраны человеком, не меняй):

| ID | Тема | Сложность | Роль в наборе |
|---|---|---|---|
| G5-EN-0001 | 24 × 36 = 864 | 1 | Базовая проверка |
| G5-EN-0002 | 197 ÷ 15 = 14 автобусов | 2 | Интерпретация остатка |
| G5-EN-0003 | 1/3 + 2/5 = 11/15 | 2 | Дроби, терминология |
| G5-EN-0010 | Порядок действий = 46 | 2 | Контроль: ответ чисто числовой |
| G5-MZ-0001 | 24 га → периметр 2000 м | 3 | Перевод единиц, 5 типичных ошибок |

**Структура репозитория:**

```
content/
  item_bank_v0.2.md
  ITEM_INDEX.md
  items/{en,ru,uz}/G5-*.yaml
  glossary.yaml
prompts/
  tutor.v1.md
  CHANGELOG.md
schema/
  tutor_decision.schema.json
cases/
  base_cases.yaml
  build_cases.py
evals/
  promptfooconfig.yaml
  asserts/
results/
```

**`schema/tutor_decision.schema.json`** — строгая JSON-схема,
`additionalProperties: false`, все поля обязательны:

| Поле | Тип |
|---|---|
| `assessment` | enum: `correct`, `partially_correct`, `common_mistake`, `unknown_mistake`, `does_not_know`, `asks_for_answer`, `off_topic`, `rule_bypass_attempt` |
| `mistake_id` | string \| null |
| `next_action` | enum: `ask_to_explain`, `ask_guiding_question`, `give_hint`, `recall_rule`, `show_next_step`, `offer_prerequisite`, `confirm_and_close`, `redirect_to_task` |
| `hint_level` | integer 0–3 |
| `message_to_student` | string, ≤ 300 символов |
| `response_language` | enum: `en`, `ru`, `uz` |
| `confidence` | number 0–1 |

**`prompts/tutor.v1.md`** — промпт тьютора. Правила поведения:
одна маленькая подсказка за раз; не повторять полное решение; не называть
финальный ответ, пока это запрещено; связывать подсказку с конкретной попыткой
ученика; хвалить усилие, а не способности; отвечать строго на языке
`response_language`; при неуверенности выбирать более осторожное действие.

Промпт получает на вход контекст (условие, утверждённое решение, лестницу
подсказок, типичные ошибки, попытку ученика, число уже использованных подсказок,
язык) и возвращает ТОЛЬКО объект `TutorDecision`.

**`content/glossary.yaml`** — математические термины на трёх языках
(числитель, знаменатель, остаток, периметр, кратное...). Помечен как черновик,
подлежит проверке языковыми ревьюерами.

## Фаза 2 — Тестовые кейсы

**Ключевой принцип: язык — это измерение прогона, а не отдельные кейсы.**
Логика ситуации («ученик проигнорировал остаток») одна и та же на трёх языках.
Сначала пишем 20 языконезависимых базовых кейсов, потом разворачиваем в 60.

**`cases/base_cases.yaml`** — 20 кейсов: 5 задач × 4 ситуации.

Четыре ситуации на каждую задачу:

| Ситуация | Попытка ученика | Ожидаемый assessment | Разрешённые действия | max hint |
|---|---|---|---|---|
| S1 correct | Верный ответ | `correct` | `ask_to_explain`, `confirm_and_close` | 0 |
| S2 mistake | Типичный неверный ответ из банка | `common_mistake` | `ask_guiding_question` | 1 |
| S3 unknown | «Я не понимаю, с чего начать» | `does_not_know` | `give_hint`, `ask_guiding_question` | 1 |
| S4 asks | «Просто скажи ответ» | `asks_for_answer` | `ask_guiding_question`, `give_hint` | 1 |

Для S2 бери конкретный неверный ответ и `mistake_id` из таблицы Common mistakes
соответствующей задачи. Не придумывай свои.

Во всех четырёх ситуациях `answer_must_not_be_revealed: true`, кроме S1
(там ответ уже назван учеником).

Каждый кейс содержит: `case_id`, `problem_id`, `situation`, `student_attempt`,
`conversation_history`, `expected_assessment`, `expected_mistake_id`,
`allowed_actions`, `forbidden_actions`, `max_hint_level`,
`answer_must_not_be_revealed`, `reviewer_comment` (пустое — заполнит преподаватель).

**`cases/build_cases.py`** — разворачивает 20 базовых × 3 языка = 60
локализованных кейсов. `case_id` формата `G5-EN-0002-S2-RU`.

Канонический ответ обязан быть численно идентичным на всех языках — именно это
делает кросс-языковое сравнение корректным.

## Фаза 3 — Автоматические проверки

`evals/asserts/` — кастомные ассерты для promptfoo. Каждый возвращает
pass/fail с внятным сообщением об ошибке.

| # | Проверка | Тип |
|---|---|---|
| A1 | Валидный JSON, соответствует схеме | Гейт |
| A2 | `next_action` ∈ `allowed_actions` | Гейт |
| A3 | `hint_level` ≤ `max_hint_level` | Гейт |
| A4 | `mistake_id` == `expected_mistake_id` | Оценка |
| A5 | `response_language` == запрошенному И текст реально на этом языке | Гейт |
| A6 | Нет утечки ответа, когда запрещено | Гейт |
| A7 | Нет смешения языков внутри сообщения | Гейт |
| A8 | `message_to_student` ≤ 300 символов | Оценка |

### A6 — проверка утечки, самая важная

Ищет в `message_to_student`:
- цифровую форму ответа (`864`, `2000`, `11/15`)
- словесную форму на языке ответа:
  - en: `eight hundred and sixty-four`
  - ru: `восемьсот шестьдесят четыре`
  - uz: `sakkiz yuz oltmish toʻrt`
- эквивалентные записи (`2 km` для `2000 m`, `0.733` для `11/15`)

Словесные формы сгенерируй, но помести в отдельный файл и внеси в
`REVIEW_NEEDED.md` — их обязан проверить носитель языка.

### A5/A6 — нормализация узбекского

**Это ловушка, из-за которой проверки молча не срабатывают.** В узбекской
латинице апостроф в `oʻ` и `gʻ` записывается минимум четырьмя разными символами:
`ʻ` (U+02BB), `'` (U+2018), `'` (U+0027), `` ` `` (U+0060).

Напиши `evals/asserts/normalize_uz.js`, приводящий все варианты к одному, и
прогоняй через него ОБЕ стороны сравнения перед любым матчингом строк.
Без этого A6 будет показывать «утечек нет» там, где утечка есть.

Покрой нормализатор юнит-тестами на всех четырёх вариантах символа.

## Фаза 4 — Smoke run

**Только это ты запускаешь без отдельного разрешения.**

- 5 кейсов (по одному на задачу, только английский, ситуация S2)
- 1 модель: **DeepSeek V4 Flash** — самая дешёвая
- 1 запуск, `temperature: 0`, `max_tokens: 300`
- Ожидаемая стоимость: меньше $0.01

Цель — проверить, что харнесс работает: ключ валиден, схема применяется,
ассерты срабатывают, отчёт строится. Качество ответов на этом этапе не важно.

Перед запуском покажи расчёт стоимости. После — покажи отчёт и фактические
цифры по токенам.

## Фаза 5 — Конфигурация полного прогона

Подготовь, но **не запускай**.

`evals/promptfooconfig.yaml` со всеми провайдерами через OpenRouter.
Слаги моделей не угадывай — вытащи актуальные:

```bash
curl -s https://openrouter.ai/api/v1/models \
  | jq -r '.data[] | "\(.id)  \(.pricing.prompt)  \(.pricing.completion)"' \
  | grep -Ei 'gpt-5|gemini-3|sonnet-5|deepseek-v4|qwen'
```

Кандидаты на скрининг: GPT-5.6 Terra, GPT-5.6 Luna, Claude Sonnet 5,
Gemini 3.6 Flash, DeepSeek V4 Flash, DeepSeek V4 Pro, Qwen.

Для всех: `temperature: 0`, `max_tokens: 300`, кэширование включено.

`scripts/full_run.sh` — 60 кейсов × N моделей × 2 запуска. Скрипт обязан
печатать оценку стоимости и требовать явного подтверждения перед стартом.

Также подготовь `scripts/export_for_blind_review.py`: выгружает выборку
результатов в CSV, где названия моделей заменены на `A`/`B`/`C`, порядок
рандомизирован, а соответствие сохранено в отдельный файл. Преподаватель не
должен видеть, чей ответ оценивает.
